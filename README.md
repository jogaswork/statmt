# MTR STATS

Telegram-бот со статистикой и управлением профитами. Запуск: `python work.py`.
Настройте `BOT_TOKEN` через переменные окружения. Токены и рабочие JSON-файлы
не должны попадать в Git. Для учёта используется постоянный том `/data`, если
он существует; иначе файлы сохраняются в текущей папке. Запускайте один
экземпляр бота на один набор файлов.

## Опубликованные профиты

В личном чате: `/admin` → «Управление профитами» → «Опубликованные профиты».
Можно листать историю, искать по воркеру, сервису, номеру сообщения,
вставить ссылку на пост или переслать его с видимым источником. Посты
идентифицируются парой канал + номер сообщения, поэтому номера из разных
каналов не смешиваются. Администраторы берутся из существующего `ADMIN_IDS`.

В карточке доступны поля профита, текст оформления и статусы «Лок»,
«Выплачено», «Ожидание». Под постом показывается одна кнопка с текущим
статусом: «🔒 Лок», «✅ Выплачено» или «⏳ Ожидание». Выбор в админке
меняет эту кнопку. Нажатия на неё всеми пользователями только молча подтверждаются;
изменять статус можно в личной админке. Для обновления канала боту нужны
права редактирования соответствующих сообщений.

Новые профиты сохраняют собственную копию шаблона и данные фото. Изменение
или удаление общего шаблона не меняет опубликованные посты. При запуске
бот добавляет кнопки к старым постам из `profits.json`, не меняя их текст
и начисления. Неудачные обновления доступны для повторной отправки через
карточку и повторяются при следующем запуске.

Старая история содержит только значения, канал и номер поста. Bot API не
позволяет получить произвольное старое сообщение по номеру. Для сохранения
старого оформления/фото перешлите оригинал через поиск. Затем замените
нужные значения в тексте переменными: `{worker}`, `{service}`, `{tp}`,
`{curator}`, `{amount}`, `{share}`. Для редактирования поля требуется его
переменная в тексте; это предотвращает изменение только статистики при
неизменном тексте канала. Смена статуса и добавление кнопок не требуют
восстановления шаблона. Пересылка не начисляет профит повторно.

Посты, которых нет в сохранённой истории, не импортируются автоматически:
невозможно достоверно определить, были ли они уже включены в старый топ.
Поиск такого поста сообщает об отсутствии записи и не меняет данные.

## Учёт и восстановление

Исторический топ сохраняется. Изменение доли корректирует только разницу;
при смене воркера прежняя доля вычитается из старого воркера, новая
добавляется новому. Ключи с `@`/`#` и различным регистром сопоставляются.
Изменение статуса или оформления не начисляет деньги.

История и топ сохраняются через `profit_transaction.json`: абсолютные
снимки обоих файлов позволяют завершить прерванное сохранение при следующем
чтении без повторного начисления. До восстановления журнала новые записи
блокируются ошибкой. Повреждённые JSON-файлы не заменяются пустыми данными.
Рабочие файлы и журнал необходимо сохранять вместе на постоянном томе.

Обновление Telegram выполняется после сохранения данных. При сетевой ошибке
правка остаётся с отметкой «Требуется обновление канала»; повторное обновление
не меняет топ. Если сама публикация завершилась неопределённой сетевой
ошибкой, проверьте канал перед новой отправкой: Bot API не предоставляет
ключ идемпотентности для отправки сообщений.

## Проверки

`pip install -r requirements.txt`

`python -m unittest discover -p 'test_*.py' -v`

Тесты используют временные файлы и подменённые ответы Telegram, без токена
и доступа к рабочим данным или каналу.
